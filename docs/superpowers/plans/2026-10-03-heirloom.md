# Heirloom Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Deliver an attractive browser app with actual EVM transactions and an encrypted two-of-three inheritance recovery demonstration.

**Architecture:** Solidity owns authorization and event history. Browser Web Crypto and Shamir sharing own encryption and decryption. A local relay stores immutable encrypted packages and signed identities/releases, while a local Hardhat chain supplies separate demonstration accounts.

**Tech Stack:** React, TypeScript, Vite, ethers v6, Solidity 0.8.30, Hardhat, Express, Privy's shamir-secret-sharing, Node test runner, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-03-heirloom-design.md`

## Global Constraints

- Three distinct guardians, two-guardian threshold; owner and beneficiary are distinct from guardians.
- Encryption keys and plaintext shares never go on-chain or to the relay.
- Only the beneficiary requests and finalizes; only the owner cancels/checks in; each guardian votes once per request.
- The full challenge window starts at quorum; cancellation invalidates earlier approvals.
- A sufficient colluding guardian quorum remains a trust assumption.
- Single-device demo roles are visibly labelled. Public networks have no demo accounts or clock bypass.
- Binding: chain ID, contract, vault ID, beneficiary encryption identity, and request ID.
- Local recovery kits preserve ciphertext and encrypted envelopes; private actor custody requires separate browser identity backup.

## Review Focus

1. Reload/network restart must not silently reuse encryption identities for a different deployment.
2. Ciphertext and release envelopes from another vault or request must be rejected.
3. Duplicate submissions must not count one guardian twice or replace immutable material.
4. Wallet rejection, RPC disconnect, and unfinished transactions must show a recoverable error.
5. Import must validate chain/deployment identity, package commitment, and shape before accepting a kit.

## Files and interfaces

- `contracts/Heirloom.sol`: vault registration and recovery state machine.
- `scripts/compile.mjs`: exports `compileContract()` and writes ABI/bytecode to `artifacts/Heirloom.json`.
- `scripts/dev.mjs`: runs Hardhat, deploys, runs the relay and Vite; graceful shutdown.
- `scripts/deploy.mjs`: public/local deployment, produces deployment JSON.
- `server/index.mjs`, `server/validation.mjs`: relay, signed identities, validated encrypted packages/releases, contract verification.
- `src/lib/crypto.ts`: `createIdentity`, `sealAsset`, `releaseShare`, `recoverAsset`, `packageCommitment`.
- `src/lib/identity.ts`: non-extractable private key persistence in IndexedDB with encrypted identity backup deferred (see docs/STATUS.md).
- `src/lib/chain.ts`: ethers provider, signer and contract operations; chain state conversion.
- `src/lib/api.ts`, `src/lib/types.ts`: typed relay protocol and public app models.
- `src/App.tsx`, `src/components/*`, `src/styles.css`: owner, guardian, beneficiary, timeline, create flow, demo help, export/import, responsive styling.
- `tests/contract.test.mjs`, `src/lib/crypto.test.ts`, `tests/relay.test.mjs`: meaningful security/validation tests.
- `README.md`, `docs/DEMO.md`, `.env.example`: setup, testnet deployment, threat model, judging script.
